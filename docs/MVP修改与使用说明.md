# MVP 修改与使用说明

本轮按 `mvp反馈.md` 调整 Web 页面及配套后端，开发分支为 `feat/mvp-feedback`。主要变化是将信息、论坛和活动统一到“动态”入口，让在校生和校友使用相同的成员权限，并补齐报名资料、评论审核和内容预览。

本文对应本地修改版，不代表线上演示站已更新。Flutter 界面没有随本轮修改。

## 本地打开方式

双击 `alumni` 文件夹下的 `start-thuie.cmd`，然后打开 [本地登录页](http://localhost:3001/login)。该启动脚本及 `thuie-local-runtime` 位于仓库外，属于本机测试环境，不会随仓库提交。

| 测试身份 | 账号 | 登录后的默认页面 |
| --- | --- | --- |
| 未毕业成员 | `20230101` | 动态 |
| 已毕业成员 | `13800000210` | 动态 |
| 管理员 | `admin@thuie.demo` | 审核队列 |
| 超级管理员 | `super@thuie.demo` | 审核队列，可进入成员权限设置 |

本地演示账号的密码均为 `Demo@12345`。

启动脚本会复用正在运行的服务。修改后端代码后，需要重启本项目后端才能加载新版本；再次双击脚本不会替换已在运行的后端。

## 成员如何使用

### 浏览和发布动态

进入动态页后，可选择全部、资讯、讨论、活动、招聘或求助，也可点击内容卡片上的标签筛选。排序支持最新发布、最早发布和最多点赞；排序在服务端对全部匹配内容执行，再分页显示。

点击“发布动态”，选择一个主标签并填写标题和正文。当前发布表单是单选主标签，不是任意多标签编辑器。讨论和求助使用帖子功能，资讯和招聘使用信息功能，活动使用活动及报名功能。

选择“活动”后，开始时间必填，结束时间可选；人数上限留空表示不限。发布后进入对应详情页。触发人工审核规则的内容不会立即进入公开动态列表。

### 报名和查看报名资料

1. 在活动详情页点击报名，进入报名资料页。
2. 填写参加者姓名和联系方式，可补充备注，然后确认报名。
3. 返回详情页查看报名状态；原有取消报名和票据功能继续保留。
4. 活动组织者或管理员在详情页点击“查看报名资料”，可查看姓名、联系方式和备注。

普通成员无法读取组织者专用的报名资料接口。人数上限在后端事务中校验，满员时会拒绝新增报名。

### 联系作者和评论

在信息、帖子或活动详情页点击作者／组织者链接，进入成员主页，再点击“发送私信”。实际发送仍使用原有私信功能及其权限规则。

信息和活动新增评论区，帖子保留原有评论区。评论通过关键词检查后发布；命中人工审核规则时进入待审核状态，仅作者和管理员可查看。点赞区域显示数量和本人是否已点赞，不展示其他点赞人的身份。

### 修改毕业状态

在“编辑个人资料”中设置“已毕业”，并填写入学和毕业年份。毕业状态不再决定成员的发布、评论、资料创建权限或可见内容范围；管理员权限仍单独管理。

为了兼容已有数据和客户端，后端仍保留 `student`、`graduate` 两个历史值，但它们共用成员权限策略。超级管理员调整成员权限时，两种状态同步更新。

## 管理员如何审核

登录后默认进入审核队列。点击内容标题，右侧抽屉显示全文、提交者、状态和已有附件；活动封面也可在预览中查看。抽屉内可通过、拒绝或下架，拒绝和下架需要填写处理说明。

举报处理页同样可以点击标题查看内容与举报原因，再选择忽略举报、移除内容或限制用户。移除和限制操作会同步处理实际内容或作者的发布权限，不只是修改举报记录的状态。用户本身被举报时，应使用限制用户，而不是移除内容。

审核沿用关键词机制，并非所有内容都先人工审批：普通帖子、评论和活动在检查通过后可直接发布；命中 `manual_review` 规则则进入待审核；命中 `block` 规则则拒绝提交。官方信息仍沿用原有管理员发布流程。

要测试人工审核，可由管理员添加一个临时测试关键词并选择“人工审核”，再由成员发布包含该词的内容或评论。确认内容进入队列，审核通过后再检查其公开可见性；测试结束后删除临时关键词。

## 后端和数据库变化

| 范围 | 变化 |
| --- | --- |
| 统一动态 | 新增 `/feed` 接口，对三类内容统一搜索、筛选、排序和分页 |
| 评论和点赞 | 评论可关联信息或活动；增加信息和活动点赞记录；审核状态变更同步维护帖子评论数量 |
| 报名资料 | 增加 `participant_name`、`contact`、`notes` 字段及校验；组织者专用接口返回这些资料 |
| 成员资料 | 新增 `/members/id`，返回公开资料和毕业状态；不返回密码或私人联系方式 |
| 审核预览 | 新增 `/admin/content/type/id`，仅管理员可访问 |
| 权限兼容 | 学生和校友共用策略；权限响应兼容 Web 的下划线字段名及旧客户端的驼峰字段名 |
| 数据迁移 | 新增 `003_mvp_feedback.sql`，通过 `schema_migrations` 记录执行状态 |

已有数据库应先备份，再从仓库的 `backend` 目录执行：

```sh
npm run db:migrate
```

随后重启后端。该命令只执行增量迁移，不重建或重新填充演示数据。不要使用 `db:reset` 升级已有数据库，它会删除现有数据。

本机修改前的备份位于仓库旁的 `thuie-local-runtime/before-mvp-feedback.dump`。本机启动脚本在启动尚未运行的后端之前，也会执行增量迁移。

## 验证记录和复测方法

本轮已通过后端 TypeScript 编译、前端类型检查和本地接口回归。浏览器中已确认登录失败后密码按钮仍可用、学生发布按钮可用、选择活动会展开活动字段、管理员登录进入审核队列，以及标题可打开完整预览抽屉。

接口回归覆盖成员权限及可见内容一致、毕业状态修改、密码确认校验、两类成员发布三类内容、筛选分页排序、点赞隐私、评论与活动审核、管理员预览访问隔离、报名必填字段及容量限制、报名资料隐私，以及举报移除实际内容。

在已配置演示数据库且本地 API 正在运行的环境中，可执行：

```sh
cd backend
node node_modules/typescript/bin/tsc -p tsconfig.build.json --incremental false
npm run test:mvp
cd ../frontend
npm run typecheck
```

接口测试会创建带唯一名称的测试内容，并在结束时清理本次内容。演示登录会话和部分审计记录可能保留。当前 Windows 本地后端使用上述 TypeScript 编译命令，避免原有 Nest Swagger 插件生成 Windows 绝对路径带来的启动问题。

建议人工复测时按“注册 → 浏览与搜索 → 发布 → 评论 → 活动报名 → 作者主页 → 管理员审核”的顺序操作，并分别检查学生和校友账号。自动回归不等于所有浏览器、移动端和线上部署都已验证。

## 范围和兼容性

- 本轮更新的是 Web 端和配套后端，尚未发布到线上。
- Flutter 界面未修改。其活动报名请求需要同步增加 `participant_name` 和 `contact`，才能调用本轮更新后的报名接口；`notes` 可选。
- 新发布入口统一的是使用流程。信息、帖子、活动仍保留各自的数据模型和详情页，便于兼容已有链接。
- 排序和标签筛选集中在新的动态列表；原列表地址会跳转到相应筛选结果。
- 修改通过 `feat/mvp-feedback` 分支及对应 PR 交付；推送代码或创建 PR 不会自动更新线上演示站。
